# Lua Shell Activity
Execute a Lua code string on the device and return its result and captured `print` output.

## Request
The activity requires a `code` string.

```json
{
	"type": "luashell",
	"args": {
		"code": "print('Hello from Lua'); return 2 + 2"
	}
}
```

## Successful Response

Successful execution returns state `0`. The value returned by the Lua chunk is placed in `res`. Captured output from calls to `print` is placed in `print`.

```json
{
	"type": "luashell",
	"state": 0,
	"res": 4,
	"print": "Hello from Lua"
}
```

If the Lua code does not call `print`, `print` is `null`.

Multiple `print` calls are joined with newline characters. Arguments passed to `print` are converted to strings and joined with tab characters, matching normal Lua print formatting.

```lua
print("value", 42)
print("done")
return { ok = true }
```

```json
{
    "type": "luashell",
    "state": 0,
    "res": {
        "ok": true
    },
    "print": "value\t42\ndone"
}
```

## Return Value Sanitization

The Lua return value is converted to a JSON-friendly structure before it is returned. The sanitizer applies these rules:

| Lua value | Returned value |
| --- | --- |
| `function` | `{ "$": "fn", "repr": "..." }` |
| `userdata` or `lightuserdata` | `{ "$": "userdata", "repr": "..." }` |
| coroutine/thread | `{ "$": "thread", "repr": "..." }` |
| `NaN` | `{ "$": "nan" }` |
| positive infinity | `{ "$": "inf" }` |
| negative infinity | `{ "$": "ninf" }` |
| string longer than 2000 characters | First 2000 characters followed by `...` |
| circular table reference | `{ "$": "ref", "to": "<path>" }` |
| table key | Converted to a string |

Tables are converted to JSON objects using stringified keys. Values that fail conversion are represented as `{ "$": "err", "message": "..." }`.

Example:

```lua
local value = {}
value.self = value
return {
	callback = function() end,
	positiveInfinity = math.huge,
	self = value
}
```

```json
{
  "type": "luashell",
  "state": 0,
  "res": {
    "self": {
      "self": {
        "$": "ref",
        "to": "root.self"
      }
    },
    "callback": {
      "$": "fn",
      "repr": "function: 0x3cdca5f0"
    },
    "positiveInfinity": {
      "$": "inf"
    }
  }
}
```

## Errors

The `reason` field identifies errors generated by the Lua shell:

| Reason | Description |
| --- | --- |
| `validation` | The `code` argument is missing or is not a string |
| `syntax` | Lua could not compile the supplied code |
| `runtime` | The compiled code raised an error while executing |

### Validation Error

```json
{
	"type": "luashell",
	"state": 4,
	"reason": "validation",
	"msg": "..."
}
```

### Syntax Error

```json
{
	"type": "luashell",
	"state": 4,
	"reason": "syntax",
	"msg": "[string \"...\"]:1: unexpected symbol"
}
```

### Runtime Error

```json
{
	"type": "luashell",
	"state": 4,
	"reason": "runtime",
	"msg": "attempt to perform arithmetic on a nil value",
	"print": "output produced before the error"
}
```

Runtime errors include any captured output produced before the failure. Syntax and validation errors do not include `print` because execution has not started.

If the QuickJS mailbox request itself fails, the response contains `msg` and `stack` without a Lua `reason`:

```json
{
	"type": "luashell",
	"state": 4,
	"msg": "Mailbox request failed",
	"stack": "..."
}
```
